Сводный отчёт о проверке API и приложения: покрытие, методика, найденные и исправленные проблемы.

## 1. Уровни тестирования

| Уровень | Инструменты | Что проверяется |
|---|---|---|
| Unit (Vitest) | 19 файлов, 103 теста | Модели, маппинг snake_case↔camelCase, ошибки API, валидации, UI-компоненты, бизнес-логика mock-слоя |
| HTTP (curl по продакшн-URL) | REST/RPC/Auth | Позитивные и негативные сценарии endpoints, RLS, пагинация, join, форматы ошибок |

| E2E (браузер) | Задеплоенное приложение на GitHub Pages | Экраны: карта, лента, профиль, состояния ошибок; сетевые запросы; консоль; PWA-манифест |
| Логи | Logs API (`docs/logging.md`) | Анализ 4xx/5xx по фактическим обращениям |

Ежёточная конфигурация: unit-тесты всегда выполняются на mock-слое (`vite.config.ts`, `test.env` очищает переменные Supabase) — детерминизм и отсутствие сети.

## 4. Найденные и исправленные проблемы

Отладка велась с помощью AI: анализ ошибок сборки/линтера, разбор логов Supabase (docs/logging.md), диагностика SQL-ошибок.

| # | Проблема | Как найдена | Исправление |
|---|---|---|---|
| BUG-1 | `create_appointment`: `INSERT … RETURNING *` без `INTO` в PL/pgSQL — функция падала при первом вызове | RPC-тест под `authenticated` (Шаг 4) — тестированием, до продакшена | Миграция 0006: `RETURNING * INTO v_result` |
| BUG-2 | Vitest подхватывал `.env.local`: unit-тесты уходили в реальную сеть (`fetch failed`, 7 падений) | Прогон тестов после появления env-файла | `vite.config.ts`: `test.env` очищает `VITE_SUPABASE_*` — тесты всегда на mock-слое |
| BUG-3 | Тестовый скрипт отправлял сломанный JSON (кавычки PowerShell, BOM в UTF-8): API отвечал 400 `bad_json` / `Empty or invalid json` | Логи `edge_logs` (400 на POST) + ответ API | Тела запросов через файлы без BOM (`UTF8Encoding(false)`) |
| BUG-4 | PWA-манифест: абсолютные пути иконок `/icons/…` и `start_url: '/'` — 404 иконок при деплое в подкаталог `/OTUS_DZ5/` | E2E-осмотр деплоя: 404 в консоли браузера, проверка манифеста | `vite.config.ts`: относительные пути (`icons/…`, `start_url: './'`, `id: './'`); после редеплоя иконки 200 |
| BUG-5 | `no-useless-catch` в `DonorProfileProvider` (обёртки try/catch только с rethrow) | ESLint | Обёртки удалены, комментарии сохранены |
| BUG-6 | Null-safety: TS не сужал `SUPABASE_URL` через `isBackendEnabled` (TS2345) | `tsc --noEmit` | Явные non-null-assertions в ветке создания клиента |
| BUG-7 | Клиентский API мог бы менять `donors.role` (самоприсвоение роли координатора) | Security-линтер Supabase при проверке RLS (Шаг 3) | `REVOKE UPDATE` + точечный `GRANT` колонок профиля (миграция 0002) |
| BUG-8 | Дублирующиеся пермиссивные RLS-политики и mutable `search_path` функций | Performance/Security-линтеры Supabase | Миграция 0003: разделение политик, схема `private`, `(select auth.uid())` |

## 5. Итоги

- **103 unit-теста** — зелёные; ESLint — 0 ошибок; `tsc` — чисто; прод-сборка — успешно (PWA precache 13 файлов);
- все endpoints покрыты по матрице «позитив / негатив / ошибки»; бизнес-правила выполняются и проверены на стороне БД;
- все найденные проблемы исправлены; регрессий не выявлено;
- остаётся операционная зависимость: подключение SMS-провайдера для полного OTP-входа (описано в docs/authentication.md) — механика Auth проверена и работает.
