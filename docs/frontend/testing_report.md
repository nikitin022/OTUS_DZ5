## 2. Найденные баги и исправления

| ID | Симптом | Причина | Исправление |
|---|---|---|---|
| BUG-1 | После заполнения профиля гость не возвращался к действию (например, к записи на донацию) — FR-1.4 нарушен | `RequireDonor` сохранял `state.from`, но `ProfilePage` игнорировал его | После сохранения профиля — `navigate(from, { replace: true })`; покрыто тестом `ProfilePage.test.tsx` |
| BUG-2 | Расстояние в ленте считалось от захардкоженного центра города; логика геолокации дублировалась в `MapPage` | Отсутствовал единый источник координат пользователя | Хук `useUserCoords` (`features/geo/model`): один запрос геолокации, уведомление при отказе; лента и карта используют его |
| BUG-3 | Флоу записи на донацию был каркасом без логики — ключевой сценарий FR-5 не проверялся | Логика откладывалась на шаг тестирования | Реализованы слоты, валидация, обработка `SLOT_TAKEN` → «Выберите другое время» и `INTERVAL_VIOLATION` → «Интервал не соблюдён»; 5 тестов |
| BUG-4 | `eslint`: `_donorId` в `MockApiClient` помечался как неиспользуемый | Префикс `_` не был разрешён в правиле | Настройка `argsIgnorePattern: '^_'` в `eslint.config.js` |
| BUG-5 | Ошибки сборки TS2307 (неверные относительные импорты) и TS6133 (неиспользуемая переменная в тесте) | Опечатки в путях при генерации файлов | Исправлены пути; сборка зелёная |
| BUG-6 | Экран записи показывал «Центр № c-1» вместо названия центра (найден при браузерной проверке по скриншоту) | `BookingPage` выводил внутренний идентификатор из URL, данные центров не загружались | Центр берётся из кэша `useCenters()` (контракт `GET /centers`), как в карточке центра; добавлены состояния skeleton/error/«центр не найден»; 2 регрессионных теста |
| BUG-7 | Warning `react-refresh/only-export-components` в `DonorProfileContext.tsx` | В файле компонента экспортировались и контекст/хук | Разделение на `profileContext.ts` (контекст + хук) и `DonorProfileProvider.tsx` (компонент) |
| FR-2.2 | На карте отсутствовал поиск по адресу/названию центра — требование Must не было реализовано | Пропущен при генерации экрана карты | Поле поиска + модель `mapFilters`, утилита `matchesSearch` (регистронезависимость, «ё/е»); 11 тестов (`MapFiltersBar`, `search`) |
| BUG-8 | Консоль браузера: предупреждения React Router о будущих флагах v7 | Флаги v7 не были включены | `future` в `createBrowserRouter` и на `RouterProvider` |

## 3. Техника отладки с AI

Использованы промпт-шаблоны из `docs/ai_debugging_prompts.md`:

1. **Ошибки консоли/сборки** — стектрейс TS2307/TS6133 разбирался по схеме
   «суть → источник → гипотезы → минимальный фикс + регрессионный тест»;
2. **Генерация исправлений** — фиксы выполнялись так, чтобы падающий
   сценарий становился тестом (BUG-1, BUG-3);
3. **Скриншоты** — визуальные баги разбирались по схеме из раздела 1:
   скриншот экрана записи («Центр № c-1») → ожидание vs реальность →
   воспроизведение в браузере → BUG-6;
4. **Браузерная проверка через Chrome DevTools (MCP)** — обход всех экранов
   (карта, лента, карточка центра, карточка заявки, запись, история, 404)
   с мониторингом консоли и проверкой на ширине 320 px (NFR-11): переполнений
   нет, ошибок в консоли нет (кроме штатного баннера отказа геолокации).

## 5. Адаптивная вёрстка (Шаг 6)

### 5.1 Аудит (замеры в браузере, авто-сканер переполнений)

Ширины: 320 / 375 / 414 / 768 / 1440 px, маршруты: карта, лента, карточка
центра, карточка заявки, запись, история, профиль, 404. Горизонтальных
переполнений нет ни на одной комбинации (`scrollWidth == innerWidth`).

### 5.2 Найденные проблемы и исправления

| ID | Проблема | Исправление |
|---|---|---|
| RESP-1 | На планшетах/десктопе оставалась нижняя таб-панель — мобильный паттерн на широком экране | Адаптивная навигация в `Layout`: нижняя панель `md:hidden`, горизонтальное меню в шапке `hidden md:flex` (с `aria-current`); контентная колонка `max-w-3xl` сохранена (Minimalist) |
| RESP-2 | В PWA на iPhone контент заходил под home indicator | `viewport-fit=cover` в meta viewport + `pb-[env(safe-area-inset-bottom)]` у нижней панели |
| RESP-3 | iOS Safari увеличивал страницу при фокусе на поле ввода (font-size 14px < 16px) | Медиа-запрос `@media (max-width: 639px)`: поля ввода 16px; на десктопе типографика компонентов не изменилась |
| RESP-4 | Серые вспышки при тапе на мобильных браузерах | `-webkit-tap-highlight-color: transparent` для интерактивных элементов |
| RESP-5 | Карта одной высоты на всех экранах | `h-80 md:h-[420px]` |

### 5.3 Проверка после исправлений

- Сканер переполнений на 320/375/414/768/1440 по всем маршрутам: чисто;
- переключение навигаций подтверждено computed style: 320 px — нижняя панель
  видима / меню скрыто; 768 и 1440 px — наоборот; карта на md+ — 418 px;
- поля ввода на мобильных — 16px (анти-зум iOS);
- скриншоты: `docs/screenshots/responsive-320-*.png`,
  `responsive-768-*.png`, `responsive-1440-*.png`;
- тест `Layout.test.tsx` (3): обе навигации, единый состав пунктов,
  `aria-current="page"` у активного пункта, переход по навигации.
