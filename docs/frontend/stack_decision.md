# Выбор технологического стека — PWA «Капля»

> Документ фиксирует решения по стеку для реализации требований `technical_specification.md`.
> Все решения проверены на соответствие нефункциональным требованиям (раздел 5 ТЗ).

## 2. Обоснование решений

### 2.1 React 18 + Vite + TypeScript

- **PWA-требования (NFR-13/14/15)**: `vite-plugin-pwa` генерирует manifest и Service Worker на Workbox «из коробки» — установка на устройство и офлайн-кэш статики закрываются стандартным решением.
- **TypeScript**: модели данных из раздела 7 ТЗ (Донор, Центр, Заявка, Запись, Отклик, Уведомление) типизируются напрямую; контракт API (раздел 8) фиксируется интерфейсами, что исключает расхождения клиента и mock-слоя.
- **Скорость разработки**: Vite даёт мгновенный HMR; NFR-4 (отклик ≤ 300 мс) проще соблюдать при быстрой итерации.
- **Альтернатива Next.js отклонена**: для MVP без реального бэкенда SSR/ISR не нужны, а Next.js усложняет PWA-настройку и деплой статики.

### 2.2 Tailwind CSS v4

- **NFR-11 (Minimalist, mobile-first, от 320px)**: utility-first подход даёт полный контроль над макетом без борьбы с готовыми темами компонентных библиотек.
- **Конфигурация в v4**: отдельный `tailwind.config` не используется — дизайн-токены (палитра, шрифты, радиусы) задаются директивой `@theme` в `src/index.css`, интеграция — через официальный плагин `@tailwindcss/vite`.
- **NFR-9 (контраст WCAG AA ≥ 4.5:1)**: палитра задаётся токенами централизованно, контрастные пары проверяются на уровне дизайн-токенов, а не на каждом экране.
- **Размер бандла**: в v4 в бандл попадают только используемые классы — важно для NFR-1 (TTI ≤ 5 с на 3G).
- **Альтернатива Material-UI отклонена**: тяжёлый рантайм, узнаваемый «материальный» стиль противоречит концепции Minimalist.

### 2.3 Leaflet + react-leaflet (OpenStreetMap)

- **FR-2 (карта центров)**: маркеры, кластеризация, попапы — базовая функциональность Leaflet.
- **Без API-ключей**: OSM-тайлы бесплатны и не требуют регистрации — нет внешних зависимостей и лимитов для MVP.
- **Лёгкость**: ~40 КБ gzip, быстрее старт карты (NFR-2: загрузка карты ≤ 3 с).
- **Альтернативы отклонены**: Google Maps и Yandex.Maps требуют API-ключей и платежных аккаунтов.

### 2.4 TanStack Query + mock-слой данных

- **FR-3.3 / NFR-3 (автообновление ленты 30–60 с)**: `refetchInterval` из коробки, без ручных таймеров и гонок.
- **Офлайн-кэш (NFR-15)**: TanStack Query кэширует результаты запросов — ранее просмотренные данные доступны без сети.
- **Контракт API сохраняется**: mock-слой реализует те же операции (`GET /centers`, `GET /requests`, `POST /appointments`, …) через интерфейс `ApiClient`. Хранение — localStorage (персональные данные не содержат чувствительной информации в открытом виде — NFR-8: хранится только mock-набор).
- **Замена на реальный бэкенд**: меняется только реализация `ApiClient`, компоненты и хуки не затрагиваются.

### 2.5 React Router v6

- SPA-навигация между экранами: карта, лента, профиль, запись, история, (позже — панель координатора).
- Поддержка вложенных маршрутов и protected-роутов (гость → донор: FR-1.4).
- Диплинки из push-уведомлений (FR-4.3) — навигация на карточку заявки по URL.

### 2.6 Web Push API

- FR-4: подписка через `PushManager` + Service Worker, генерируемый `vite-plugin-pwa`.
- В MVP подписка регистрируется в mock (`POST /subscriptions`); дедупликация заявок (FR-4.2) реализуется на уровне mock-сервиса.
- iOS-совместимость — через поддержку Web Push в Safari (NFR-17).

### 2.7 Vitest + React Testing Library

- Единый раннер с Vite — нулевая дополнительная конфигурация.
- RTL — тестирование с точки зрения пользователя (доступность, роли ARIA) — помогает проверять NFR-10 (навигация с клавиатуры).

## 3. Ограничения стека и риски

| Риск | Митигирование |
|---|---|
| Leaflet на iOS имеет нюансы с жестами | Отдельная настройка `touchZoom`, тестирование на реальном устройстве |
| Tailwind требует дисциплины именования | Вынесение повторяющихся паттернов в компоненты + `@apply` |
| Mock-слой может «протечь» в UI | Доступ только через `ApiClient`-интерфейс; прямой импорт mock-хранилища в компонентах запрещён |
| Персональные данные в localStorage | Хранить только mock-профиль без реальных телефонов; ключи без PII в значениях (NFR-8) |

## 4. Что НЕ входит в стек MVP

- Реальный бэкенд / БД (раздел 10 ТЗ: mock-слой допускается);
- SSR / SSG (Next.js и аналоги);
- Стейт-менеджеры вроде Redux/Zustand — на MVP достаточно Context + TanStack Query;
- Фреймворки тестирования E2E (Playwright) — подключим на этапе тестирования/отладки.
