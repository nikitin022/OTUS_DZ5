# Функциональные требования — PWA «Капля»

> Документ фиксирует функциональность MVP на основе `technical_specification.md` (раздел 4).
> Идентификаторы FR-xxx соответствуют ТЗ; приоритеты — MoSCoW.

## 1. Область MVP: ядро функциональности

Ядро MVP — **пять функциональных блоков** с приоритетом Must. Они реализуются в первую
очередь и закрывают ключевые сценарии донора: от профиля до записи и истории.

| № | Блок | FR | Приоритет |
|---|---|---|---|
| 1 | Профиль донора и онбординг | FR-1 | Must |
| 2 | Карта центров и карточка центра | FR-2 | Must |
| 3 | Живая лента потребностей | FR-3 | Must |
| 4 | Push-уведомления | FR-4 | Must |
| 5 | Запись на донацию и история донаций | FR-5, FR-6 | Must |

Следующий этап (после ядра): координаторский контур — **FR-7, FR-8** (публикация заявок,
отклики). Затем — Should-функции (FR-4.4, FR-4.5, FR-5.4, FR-9.x).

## 2. Детализация требований

### 2.1 Профиль донора и онбординг (FR-1)

| ID | Требование |
|---|---|
| FR-1.1 | Создание профиля: группа крови (1–4), резус-фактор (+/−), радиус поиска 1–500 км |
| FR-1.2 | Явное согласие на геолокацию и push-уведомления до использования функций |
| FR-1.3 | Редактирование профиля с сохранением изменений |
| FR-1.4 | Гость видит карту и ленту; запись и push требуют входа (вход по телефону + одноразовый код, mock) |

Валидации: «Укажите группу крови», «Радиус от 1 до 500 км».

### 2.2 Карта центров (FR-2)

| ID | Требование |
|---|---|
| FR-2.1 | Маркеры центров в радиусе донора: расстояние, статус «открыто/закрыто» |
| FR-2.2 | Поиск по адресу/названию; фильтры «Открыто сейчас», «Срочно» |
| FR-2.3 | Карточка центра: адрес, график, телефон, нужные группы, кнопка «Записаться» |
| FR-2.4 | «Построить маршрут» — открытие внешних карт (deeplink) |

Пустые состояния: «Нет центров в радиусе» + «Изменить радиус»; при отказе в геолокации — баннер + ручной ввод адреса.

### 2.3 Живая лента потребностей (FR-3)

| ID | Требование |
|---|---|
| FR-3.1 | Заявки: группа, объём, срочность, расстояние, прогресс, время обновления |
| FR-3.2 | Фильтры по группе крови и срочности; «Сбросить фильтры» |
| FR-3.3 | Автообновление каждые 30–60 с без перезагрузки страницы |
| FR-3.4 | Пагинация «Показать ещё» |

Сбои: при ошибке автообновления — «Обновить сейчас»; пустой фильтр — «Сбросить фильтры».

### 2.4 Push-уведомления (FR-4)

| ID | Требование |
|---|---|
| FR-4.1 | Push при появлении заявки на группу донора в его радиусе |
| FR-4.2 | Дедупликация идентичных заявок |
| FR-4.3 | Тап по push открывает карточку заявки (диплинк) |

При отклонённом разрешении — инструкция «Как включить». Настройки типов/частоты (FR-4.4) и напоминания за 24 ч (FR-4.5) — Should, после ядра.

### 2.5 Запись на донацию (FR-5)

| ID | Требование |
|---|---|
| FR-5.1 | Календарь и выбор слота (дата/время) |
| FR-5.2 | Проверка интервала между донациями ≥ 60 дней; блокировка слота при нарушении |
| FR-5.3 | Создание записи со статусом «Ожидает подтверждения» |

Сценарии: занятый слот — «Выберите другое время»; интервал < 60 дней — «Интервал не соблюдён».

### 2.6 История донаций (FR-6)

| ID | Требование |
|---|---|
| FR-6.1 | Записи: дата, место, объём, тип, статус, индикатор «Интервал соблюдён» |
| FR-6.2 | Пустое состояние «У вас пока нет записей» |

### 2.7 Контур координатора (FR-7, FR-8) — второй этап

| ID | Требование |
|---|---|
| FR-7.1 | Создание/редактирование заявки: группа, объём (≥ 1 мл), срочность; валидация полей (FR-7.3) |
| FR-7.2 | Закрытая заявка исчезает из активной ленты |
| FR-8.1 | Счётчик откликов; контакты откликнувшихся — только координатору |
| FR-8.2 | Статусы заявки: активна / закрыта |

## 3. Контракт API (mock-слой)

Mock-слой реализует контракт раздела 8 ТЗ через интерфейс `ApiClient`:

| Операция | FR |
|---|---|
| `GET /centers` | FR-2 |
| `GET /requests` | FR-3 |
| `POST /requests` | FR-7 |
| `PATCH /requests/{id}` | FR-7 |
| `POST /appointments` | FR-5 |
| `PATCH /appointments/{id}` | FR-5 |
| `POST /subscriptions` | FR-4 |
| `GET /donors/{id}/history` | FR-6 |
| `GET /requests/{id}/responses` | FR-8 |

Хранение: localStorage. Ошибки API возвращают человекочитаемое сообщение + код.

## 4. Обязательная матрица обработки ошибок (раздел 6 ТЗ)

| Функция | Сценарий | UX-решение |
|---|---|---|
| Профиль | Нет группы крови | Подсветка + «Укажите группу крови» |
| Профиль | Радиус 0 или > 500 км | «Радиус от 1 до 500 км» |
| Карта | Нет центров в радиусе | Пустое состояние + «Изменить радиус» |
| Карта | Геолокация запрещена | Баннер + ручной ввод адреса |
| Лента | Фильтр пуст | «Сбросить фильтры» |
| Лента | Сбой автообновления | «Обновить сейчас» |
| Push | Разрешение отклонено | Инструкция «Как включить» |
| Запись | Слот занят | «Выберите другое время» |
| Запись | Интервал < 60 дней | «Интервал не соблюдён» |
| Координатор | Нет роли | «Только для координаторов» |
| Все экраны | Нет сети | Скелетон, баннер «Нет соединения» + «Повторить», офлайн-кэш |

## 5. Нефункциональные ориентиры реализации

- TTI ≤ 5 с (3G); карта ≤ 3 с; отклик UI ≤ 300 мс; лента — поллинг 30–60 с.
- Mobile-first от 320px, стиль Minimalist, русский язык интерфейса.
- Контраст ≥ 4.5:1 (WCAG AA), полная навигация с клавиатуры.
- PWA: manifest + Service Worker, офлайн-доступ к ранее просмотренным данным.
